# 実装指示 ⑧:写真アルバムと散歩の統合(A-8)

> **⚠ これは他の7項目がすべて終わってから着手する。** 唯一「ゼロから作る」タスク。
> **⚠ 特に ⑥(モード表示の統合)を先に終わらせること。** アルバムは新しいモードとして入るので、統合前に作ると後で直す羽目になる。

## 着手前に必ず

```
grep -rn "exif\|EXIF\|album\|Album" js/ index.html          # → 現時点で0件のはず
grep -rn "latLonToXZ\|xzToLatLon" js/legacy/part7.js
grep -rn "indexedDB\|openDB\|IDB" js/legacy/*.js | head
grep -rn "ModeRegistry.registerMode" js/legacy/*.js
```

既存の設計書と検証ファイルを必ず先に読むこと:
- `FEATURE_PHOTO_ALBUM.md`(設計。10KB)
- `exif-test.html`(EXIF読み取りの動作検証済みコード。5.7KB)
- `IMPL_PROMPT_20260803_PHOTO_ALBUM.md`(過去の指示書)

## 前提(調査済みの事実)

1. **アルバム機能は1行も実装されていない。** `exif|EXIF|album|Album` の文字列が `js/` にも `index.html` にも存在しない。
2. あるのは設計書と単独の検証ファイルだけ。
3. 座標変換 `latLonToXZ` / `xzToLatLon` は既にある(`part7.js`)。
4. IndexedDB は OSM キャッシュで既に使われている。
5. **Web にはフォトライブラリへの権限APIが存在しない。** 自動取り込みは不可能。`<input type="file" multiple>` でユーザーが明示的に選ぶ形が唯一の道(設計書にも記載済み)。

## A-8a:アルバム本体(前提となる部分)

### やること

1. **写真の読み込み**
   - `<input type="file" multiple accept="image/*">` で選択。
   - `exif-test.html` で検証済みの EXIF パースコードをそのまま持ち込む。`GPSLatitude` / `GPSLongitude` / `GPSLatitudeRef` / `GPSLongitudeRef` / `DateTimeOriginal`、あれば `GPSImgDirection`(撮影方位)も読む。
   - GPS情報が無い写真は「位置なし」として弾き、**何枚弾いたかをユーザーに伝える**(黙って消さない)。

2. **保存(IndexedDB)**
   - 保存前に**長辺512pxにリサイズ**してから保存する。原寸を持つとメモリを食う。
   - レコード:`{ id, lat, lon, dateTaken, heading, thumbBlob }`
   - ⚠ **キャッシュキーは必ず絶対座標(緯度経度)ベースにすること。** 原点相対のキーにすると都市をまたいだときに衝突する。過去にOSMキャッシュでまさにこれをやって、密集地ジャンプ後の生成不全を起こしている([[project_isehara_game_dense_city_jump_diagnosis]])。

3. **3D空間への配置**
   - `latLonToXZ` でワールド座標へ。高さは既存の `getGroundY` を使って地面に立てる(**`getGroundY` は読むだけ。改変しない**)。
   - 表示は板ポリゴン(`PlaneGeometry` + `CanvasTexture`/`Texture`)。`GPSImgDirection` があればその方向を向ける。無ければカメラ正対(ビルボード)。
   - **上限を最初から設計に入れる**:`scene` に同時に出すのは**近い順20枚まで**。それ以外は破棄する(ピンだけ残す)。数を増やす機能に個別上限を付けないと破綻することは学習済み([[feedback_per_building_decoration_budget]])。

4. **プライバシー(仕様として明記する)**
   - **写真も位置情報もサーバーに一切送らない。すべてブラウザ内で完結する。**
   - これは安全性のためだけでなく、**サーバー改修がゼロになるので実装も簡単になる**。
   - `server/server.js` には一切触らないこと。

### 完了判定(A-8a)

- 手持ちの写真10枚を読み込むと、正しい場所にピン/写真が立つ。
- ブラウザを閉じて開き直しても残っている。
- 遠方の写真(旅行先など)を含めて読み込んでも、その場所へジャンプすれば見える。
- 100枚読み込んでも FPS が落ちない(上限が効いている)。

## A-8b:散歩との統合(ここが本題)

A-8a が動いたら、以下の3つを足す。**すべて安い。**

1. **近接通知** — 写真の撮影地点から100m以内に入ったら HUD に `📷 この先に3枚の思い出`。
   - **③(A-1)の駅名・建物名の近傍探索とまったく同じ仕組みで作れる。** ③ が終わっていれば流用するだけ。
2. **空中の写真** — 撮影地点で近づくと写真が大きく表示される。
3. **ミニマップに撮影地点のドット** — 一番安い。ミニマップ描画(`part7.js`)にレイヤーを1枚足すだけ。

---

## A-8c:GPS追従モードとの掛け算(このタスクの本当の価値)

**実際にその場所に行くと、その場所の思い出が出てくる。**

- GPS追従モード(モードA)は**既に実機で動作確認済み**なので、A-8b がそのまま乗る。
- `IDEA_WORLD_CANVAS.md` が「③(写真の位置マッピング)は多人数が揃わなくても単独で価値が完結する」と書いているのは、まさにこれ。**アルバム × GPS追従だけで独立した1つの体験になる。**

### 完了判定(A-8c)

- GPS追従モードで実際に外を歩き、思い出の場所に近づくと写真が出る。

## モード登録

- アルバムは `ModeRegistry.registerMode({ id: 'album', label: 'アルバム', category: 'view', ... })` として登録する。
- ⑥ で統合した `#modeBadge` に自動的に出ることを確認する。**専用のバッジを新設しないこと。**

## やらないこと

- 写真の公開・共有機能(World Canvas の①②)は**このタスクに含めない**。公開はモデレーション設計が先に必要で、別の話。
- フォトグラメトリ(写真→立体化)は含めない。
- サーバー側の実装は一切しない。

## i18n

- 表示文言はすべて既存の `t()` / `I18N` 辞書(`part1.js` 冒頭)に追加する。**自前の辞書を作らないこと**(過去に audio.js で自前辞書を作って統合し直した経緯がある)。
