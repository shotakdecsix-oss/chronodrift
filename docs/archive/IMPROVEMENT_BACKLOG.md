# 【新規】V-13: 橋の桁高が高すぎる — 特に狭い川

## 症状
道路・線路が川を渡る橋の高さが不自然に高い。**川幅が狭いほど不自然さが大きい。**

## 原因は3つ重なっている

### (1) 単位バグ — クリアランスが意図の2倍になっている ★本命

**該当**: `part3.js:1093, 1154`（一般の橋）/ `part3.js:1124`（最低桁下）/ `part3.js:960`（高速道路）

```js
// part3.js:1093
const BRIDGE_CLEARANCE_ABOVE_WATER_M = 2.0; // 水面から橋桁下端までの最低クリアランス(実m)
```
```js
// part3.js:1154
    const needed = Wmax + BRIDGE_CLEARANCE_ABOVE_WATER_M * ELEV_SCALE;
```

定数のコメントは「**実m**」と明記している。ところが `ELEV_SCALE`（= 2.0、`part5.js:134`）を掛けている。

`ELEV_SCALE` は**実標高をゲーム高さへ誇張変換する係数**で、`getGroundY` や `waterSurfaceYAt` の戻り値には既に適用済み。一方、**プレイヤー（背丈 1.8、`part9.js:1256`）・建物の高さ・道路幅（`part3.js:1318` で 4.2m など）はすべて 1:1**。

つまり `Wmax` も `needed` もゲーム単位で、**その差分にさらに 2.0 を掛ける理由がない**。結果として:

| | 意図 | 実際 |
|---|---|---|
| 水面からのクリアランス | 2.0 | **4.0 ゲーム単位** |
| 水面自体の浮き（`buildAreaPoly(..., 0.5, ...)`、`part4.js:263`） | +0.5 | +0.5 |
| **地面からの桁高 合計** | 2.5 | **4.5 ゲーム単位** |

プレイヤーの背丈 1.8 に対して **桁が 2.5 人分の高さ**。小川に架かる橋としては明らかに高い。

`BRIDGE_MIN_CLEARANCE_M`（`part3.js:1081`、コメントも「実length, m」）にも同じ `* ELEV_SCALE` が掛かっている（`part3.js:1124`）。高速道路側（`part3.js:960`）も同じ式。

**→ `* ELEV_SCALE` を外すだけで桁高が半分になる。** 3〜4箇所の1行修正。

### (2) 川幅を一切見ていない

`BRIDGE_CLEARANCE_ABOVE_WATER_M` は定数で、**幅3mの用水路も相模川も同じクリアランス**。実際には:

- 小さな水路・用水路: 桁下はほぼ路面と同じ（0〜0.5m）
- 中小河川: 1〜2m
- 大河川・可航河川: それ以上

現状は全部同じ扱いなので、**狭い川ほど「用もなく持ち上がった橋」に見える**。これがユーザー報告の「狭い川の時に不自然さが大きい」の直接の説明。

**→ 水面ポリゴンの幅（または `bridgeInfo` の水掛かり区間長 `s1 - s0` × wayLen）からクリアランスを決める。** 例: 水掛かり区間 < 10m なら 0.3、< 30m なら 0.8、それ以上は 1.5〜2.0。

### (3) 立ち上がりが「wayの長さに対する割合」なので、短い橋ほど急勾配になる

```js
// part3.js:1094
const BRIDGE_RAMP_FRAC = 0.15; // 橋の両端から何割の区間を立ち上がりの助走に使うか
```
```js
// part3.js:1156-1159
    if (f >= s0 && f <= s1) return needed; // 水に掛かる区間は一律満額
    let edgeT;
    if (f < s0) edgeT = 1 - Math.min(1, (s0 - f) / BRIDGE_RAMP_FRAC);
    else edgeT = 1 - Math.min(1, (f - s1) / BRIDGE_RAMP_FRAC);
```

ランプは **way長の15%**。40m の橋なら片側 6m で 4.5 単位を登る → **勾配 75%**。長い橋では緩やかなのに、短い橋ほど壁のようになる。

さらに `WATER_QUERY_MARGIN = 20`（`part4.js:466`）により、水域ポリゴンの**外側20mまで「水の上」と判定される**。短い橋（40m級）だと `s0≈0, s1≈1` になり、`f >= s0 && f <= s1` が全区間で真 → **橋全体が満額の高さ**になり、**両端で隣の道路（地面の高さ）との間に 4.5 単位の垂直な段差**ができる。

加えて水面サンプリングは 20m 間隔（`part3.js:1131` `const STEP = 20;`）なので、**狭い川はサンプルに当たったり当たらなかったりする**。当たれば満額の段差、外れれば `Wmax === null` で完全に平ら。**似た橋なのに結果がバラバラになる**のはこれ。

**→ ランプを絶対距離（例 25〜40m、wayLen でクランプ）にする。サンプリング間隔を `Math.min(20, wayLen/8)` にする。**

## 修正の順序（推奨）

1. **`* ELEV_SCALE` を外す**（`part3.js:960, 1124, 1154`）— 1行×3。これだけで桁高が半分になり、体感の大半が解消するはず
2. **クリアランスを水掛かり幅で可変に** — 狭い川の「持ち上がり」が消える
3. **ランプを絶対距離に、サンプリングを細かく** — 段差と個体差が消える

**注意（対で検算すべき定数）**: `ELEV_SCALE` は橋の桁下（`part3.js:960,1124,1154,1246`）と海面高（`part4.js:679,692`）の両方に効いている。V-13 で外す箇所と、V-22（`ELEV_SCALE` そのものを 1.0〜1.3 に下げる案）は**同じ場所を触る**ので、片方を先にやるなら他方の前提が変わることを意識する。過去に「橋の水没」で10回往復した経緯があるため、**1と2を入れたら実機で相模川（大河川）と市内の小川の両方を必ず見る**こと。
