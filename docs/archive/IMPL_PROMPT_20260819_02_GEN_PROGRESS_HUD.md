# 実装指示 ②:生成の進捗を通常HUDに出す(C-2)

## 着手前に必ず

```
grep -rn "debugTileOverlay\|setDebugTileOverlay\|status = '" js/legacy/part9.js
grep -rn "getElementById('status')\|#status" js/legacy/*.js index.html
```

## 前提(調査済みの事実)

1. タイルごとの状態は `js/legacy/part9.js:236-242` で**既に6段階に判定されている**:

   | status | 意味 | 🩺オーバーレイの色 |
   |---|---|---|
   | `unqueued` | まだキューに入っていない | 灰 |
   | `fetching` | OSM取得中 | 赤 |
   | `gaveUp` | 取得を諦めた | 紫 |
   | `waitTerrain` | 道路は来たが地形待ち | 青 |
   | `buildingPending` | 建物クエリ待ち / メッシュ生成待ち | 橙 |
   | `done` | 完了 | 緑 |

2. デバッグ用オーバーレイ `#debugTileBtn`(🩺)が既にあり(`part7.js:1080-1090`)、この判定を使って色分け表示している。
3. `#status` という DOM 要素が index.html に既にある。
4. **つまりデータは完全に揃っている。足りないのは常用者向けの見せ方だけ。**

## 目的

起動直後・ジャンプ直後の「何も出てこない時間」に、**遅れているのか壊れているのかをユーザーが区別できるようにする**。特に Render のコールドスタート(起動30〜45秒)と重なると「開いたけど何も出ない」で閉じられてしまう。

## やること

### Phase 1:1行のステータス表示

- 既存の status 集計ループに `counts[status]++` を足す(**新しい走査を増やさない**。既存ループに相乗りする)。
- `done` 以外が1枚でもあるときだけ `#status` に表示。全部 `done` になったら3秒後にフェードアウト。
- 基本形:`🛰 周辺を生成中… 12/25`

### Phase 2:詰まりの種類で文言を変える(ここが本題)

最も多い status(または優先度順)で文言を切り替える:

| 条件 | 文言 |
|---|---|
| 起動から30秒未満 かつ ほぼ全部 `unqueued` | `⏳ サーバーを起こしています…`(Renderコールドスタート対策) |
| `fetching` が最多 | `🛰 地図データを取得中… n/m` |
| `waitTerrain` が最多 | `⛰ 地形を待っています… n/m` |
| `buildingPending` が最多 | `🏢 建物を配置中… n/m` |
| **`gaveUp` が1枚以上**(最優先で表示) | `⚠ 一部の地図データを取得できませんでした(自動で再試行します)` |

- `gaveUp` の警告が**このタスクで一番価値がある部分**。過去に何度も「生成が止まった」と報告された状態が、はっきり言葉になる。

### Phase 3(任意・Phase1/2の後で判断):ミニマップに重ねる

- ミニマップ描画(`part7.js`)に、未完了タイルを薄い灰色の四角で重ねるレイヤーを1枚足す。
- 「どっちの方向がまだ生成されていないか」が分かり、遅い方向へ歩かない行動を誘導できる。

## やらないこと

- 🩺 デバッグオーバーレイの挙動は一切変えない。あれはあれで残す。
- 新しいタイル走査ループを追加しない。

## 実装上の勘所

- **毎フレーム DOM を書き換えないこと。** 集計は既存のオーバーレイ更新周期に相乗りし、**文言が前回と変わったときだけ** `textContent` を更新する。
- 文言は必ず **i18n を経由する**。`part1.js` 冒頭の辞書(ja/en 両方)に追加し、`data-i18n` の仕組みに乗せること。自前の辞書を作らない(過去に audio.js で自前辞書を作って統合し直した経緯がある)。

## 完了判定

1. 起動直後に `⏳ サーバーを起こしています…` → `🛰 地図データを取得中… n/m` と進み、完了すると消える。
2. 遠方へジャンプしても同じように出る。
3. 意図的にオフラインにする等で `gaveUp` を発生させると、警告文が出る。
4. **表示を足したことで FPS が落ちていない**(DevTools の Performance で確認)。
5. 日本語・英語の両方で正しく出る。
