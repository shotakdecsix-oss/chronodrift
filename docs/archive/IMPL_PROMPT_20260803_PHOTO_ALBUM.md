## 厳守事項

### 1. 実データの生成を絶対に邪魔しない

このプロジェクトの最優先原則は「**地図データ(道路・線路・建物)の忠実性**」。
写真パネルはその上に乗せる装飾であり、**実データの生成予算を 1 バイトも奪ってはならない**。

- 既存のチャンクキュー / OSM タイルキュー / 建物キューに写真を積まない
- `bMax` などの既存カウンタに含めない
- 専用の管理配列で完全に独立させる
- 画像デコードは同時 2 枚まで。フレームを跨いで分散させる

### 2. XZ 座標をキャッシュしない

`recenterOrigin()` でジャンプのたびに `MID_LAT`/`MID_LON` が変わる。
**写真は lat/lon を正とし、XZ は使うたびに `latLonToXZ()` で算出する。**
ジャンプ時は全パネルを破棄して新原点で組み直すこと。

過去に同種のバグを複数回踏んでいる。ここは設計段階で潰しておくこと。

### 3. 地形の再スナップに対応する

支柱の根本は `getGroundY()` にスナップするが、NEAR 地形が後から更新されると浮く。
2026-08-02 に「ジャンプ後に木・信号機が浮く」という不具合が実際に起きている
(プール系が再スナップ対象外だったのが原因)。

写真パネルは個体レコードを持つため既存の `resnapPropsAndTreesInBounds` には乗らない。
**自前で再スナップ対象リストを持ち、NEAR 地形更新時に呼ばれるようにすること。**

### 4. メモリを丁寧に扱う

- `createImageBitmap` の結果は**必ず `close()`** する(iOS で顕著にメモリを食う)
- パネル破棄時に `texture.dispose()`
- Geometry は共有インスタンスを使い回す
- 取り込みの同時実行は 3 まで

過去に GPU メモリ 2GB でクラッシュした経緯がある。新規に確保するものは全て解放パスを用意すること。

### 5. 既存の挙動を壊さない

`part7.js` / `part9.js` / `part1.js` への変更は**フック 1 行程度に留める**。
ロジック本体は新規の `js/legacy/part11.js` に置く。

### 6. 座標系の規約に注意

このプロジェクトには `player.rotation.y`(Frame A)と `camYaw`(Frame B)という **180° 異なる 2 つの規約**がある。
ビルボードの向きを実装する際は、どちらを基準にしているか必ず確認すること。
「なんとなく合った」で `Math.PI` を足し引きしない。

## 実装スコープ

### やること

1. IndexedDB `photoAlbum` の読み書き(設計書 §5 のスキーマ)
2. 一括取り込み + 重複排除 + 進捗表示(§6)
3. 近傍のフォトパネル生成・破棄・ビルボード更新(§7)
4. ジャンプマップへの写真マーカー表示 + クラスタリング + タップでジャンプ(§8)
5. パネルタップで拡大表示(§9)
6. 設定トグル: ON/OFF、表示距離、全削除(§10)
7. i18n キーの追加(日本語・既存言語に合わせる)

### やらないこと

- ゲーム内カメラ(フェーズ2)
- 元画像の保存(サムネ 512px のみ)
- サーバ側の変更(完全にクライアント内で完結させる)

## 使用ライブラリ

`exifr@7.1.3` (UMD)。`index.html` の Leaflet の隣に追加:

```html
<script src="https://cdn.jsdelivr.net/npm/exifr@7.1.3/dist/full.umd.js"></script>
```

`exifr.gps(file)` は File/Blob を直接受けられる。**ArrayBuffer に展開しないこと**(メモリ削減のため)。

読み込み失敗時は写真機能だけを無効化し、ゲーム本体は通常起動すること。
