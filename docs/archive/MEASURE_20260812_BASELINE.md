# 実測手順 2026-08-12 — 水面(A)と性能(C)をまとめて計る

対象: ロールバック後のベースライン `7dc2127`(= `js/legacy/` は `e98f5a8` 相当)。
実機確認で「黒い穴なし・陸の水面化なし・大きな四角化なし / **水面の陸化あり・浮き上がりあり**」を確認済み。

このラウンドは**修正しない**。数値を取って原因を1つに絞るまでが目的。
コード変更もデプロイも不要(コンソールに貼るだけ)。

## 手順

1. PC Chrome で本番URLを開く。**F12でDevToolsを先に開く**(ログを取りこぼさないため)。
2. コンソールに `DEBUG_PROBE_20260812_WATER_PERF.js` の中身を**全文貼って Enter**。
   `[probe] 導入完了` が出ればOK。
3. **NY(マンハッタン)へジャンプ**。ハドソン川かイーストリバーの上、
   できれば「川なのに地面になっている場所」が見える位置へ。
4. そのまま **60秒ほど待つ**(タイル取得が落ち着くまで)。歩き回ってもよい。
5. コンソールで `__cdReport()` を実行。
6. 出力の (A-1) の表にある **gmaps リンクを2〜3個開いて、本当に水面かを目視で突き合わせる**。
   陸なら正常なので候補から外す。ここまでやらないと数字の意味が確定しない。
7. コンソールを右クリック → *Save as...* でログ全文を保存し、共有。

余力があれば同じ手順を **伊勢原/相模川** でも1回(海 vs 川の切り分けになる)。

## 何を見ているか

### (A-1) 海が陸のまま残る経路 — 3つの候補を分離する

`processCoastlineFill`(part4.js)は、タイルを見た瞬間に `seenCoastlineTiles.add(key)` して
**二度と再試行しない**。その直後に2つの早期 `continue` がある:

```js
seenCoastlineTiles.add(key);
if (openWays.length === 0) continue;   // ← このバッチの応答に海岸線が1本も無かった
...
if (nearWays.length === 0) continue;   // ← 3000m以内に海岸線が無かった
```

つまり陸化には少なくとも3つの入口がある:

| 候補 | レポート上の見え方 | 意味 |
|---|---|---|
| **(a) 応答に海岸線が入っていなかった** | `openWaysInBatch = 0`、`phase12Log = (ログ無し)` | タイルのbbox問合せに coastline way がかからなかった。岸から2枚以上離れた広い水面で起きうる。印だけ付いて**永久に陸** |
| **(b) 判定が陸と答えた** | `phase12Log` に `built=0 empty=N` | ribbonが退化 or Phase2の5点投票が3票未満 |
| **(c) sea予算切れ** | `budgetFail > 0`、`sea予算残 = 0` | 川(`water`)には再試行キュー `pendingAreaWaterPolys` があるが、**海(`sea`)には無い**ので捨てたら永久に喪失 |

コメントには「coastlineの位置は実データなので同じタイルへ何度到着しても結果は変わらない」と
書かれているが、これは**バッチ応答の中身に依存する**ので前提として成立しない可能性がある。
(a) が支配的ならここが本命。まず数を数える。

> 大原則との関係: 「保留を作るなら回収経路と滞留計器を同じコミットで入れる」。
> `seenCoastlineTiles` は回収経路の無い保留になっている疑いがある。

### (A-4) 浮き上がり

- 固定海面Y = `seaLevelY() + seaYOffset()`。`seaYOffset()` は
  `LAND_FLOOR_MARGIN_M * ELEV_SCALE + 0.3` で、地形の底上げ量を必ず上回るよう置かれている。
  **海が浮くなら、この +0.3 の下駄そのものが見えている**可能性がある(海は常に地形より高い設計)。
- 川は `waterProfile`(岸ノードのビン集計)。表の `水面が地形より高い_m` が
  数m単位なら集計側、0.15前後なら設計通り。
- `terrainY` が `(欠測null)` の行があれば、そこはDEM欠測。**0に潰さず null のまま見る**。

### (C) 性能

引き継ぎに載っていた `kind=lake` と `pendWater` は、**ロールバックした側のコードにしか存在しない**
(現ベースラインを grep しても1件も出ない)。つまりあの性能ログは壊れたビルドの数字であり、
**そのまま今の課題として引き継いではいけない**。取り直しが必要。

見る順:

1. `[fetch]` の `queue` と `maxActiveAgeMs` — 供給側が詰まっているか
2. `[buildgen]` の `generated/2s` と `requeued/2s` — 空回りしているか
3. `renderer.info` の `geometries` 推移 — 単調増加ならリーク

## このラウンドで**やらないこと**

- 地形に穴を開ける / 半平面逐次交差でセルを切る(いずれも失敗確定済み)
- coastline由来ポリゴンを地形マスクに使う(構築物であって実測輪郭ではない)
- `side: DoubleSide` を巻き順ミスの保険にする
- 症状を見て複数箇所を同時に触る(1変更=1コミット=単独で検証できる単位)
