# 実装指示 v2: 橋の水没 — 実測データで確定した真因

作成: 2026-08-03 / PC Chrome DevTools の実測ログにより確定。v1(`IMPL_PROMPT_20260803_BRIDGE_WATER.md`)の
M1(`_dirty`握りつぶし)は修正済みで正しかったが、**本症状の原因ではなかった**。

---

## 0. 実測で分かったこと

### 橋側は正常に作られている(M1は原因ではない)

計測表の全行で `式deck` と `実mesh` の差が **一定の +0.40**(道路の `yOff`)。
→ **メッシュは常に最新の式どおりに作られている。** 古いメッシュが残る問題は解消済み。

### 真因: 標高の「欠測」が水位に化けている

```
[water] profile bins=20 min=-9.3 max=0.3 near=yes     ← 実データと欠測が混在
[water] profile bins=8  min=0.3  max=0.3 near=NO      ← 全ノード欠測
[water] profile bins=38 min=-8.7 max=0.3 near=NO
[water] profile bins=14 min=-9.1 max=0.3 near=NO
GET https://cyberjapandata.gsi.go.jp/xyz/dem_png/14/…png 404 (Not Found)   ← 多数
```

原因の連鎖:

1. `part6.js terrainY` … `return sampleGrid(wideElev, …) || 0;`
   → **データ無し(null)を 0 に潰している。「欠測」と「標高0m」を区別していない。**
2. `part5.js farNodeY` … `return terrainY(…) || 0;` → 同上。
3. `part4.js _computeWaterProfile` … 各ビンで **最大値** を取る。
   → 欠測ノード1つで、そのビンが `0` になる。
4. さらに **累積最大で上流へ伝播** させる。
   → **たった1点の欠測が、川の片側全域の水位を 0 へ引き上げる。**

### 数字の検算(実測値と一致する)

- `elevBase = 4.8`、`ELEV_SCALE = 2.0` → ゲーム高さ0 = 実標高4.8m
- この地域の地面: `足元 = -6.19`(実標高 約1.7m)
- 欠測由来の水位: `0.3` → 地面より **6.5 ゲーム単位 = 実測3.2m 高い**
- 橋桁: `実mesh = -5.5` → 水面の **5.8 単位下**。完全水没。

**特定の橋の問題ではなく、GSIタイルが404を返す全域で恒常的に起きている。**
「頻発する」「橋によって埋もれたり埋もれなかったり」の説明もこれで付く。

### 橋側に残っている2つの欠陥(こちらも実測で確認)

- **サンプリング点がズレている(疑い3・確定)**
  `水位` が非NULLなのに `差` がマイナスの行がある(wid `15723866` = -0.83、
  `816973380`/`816973482` = -1.33、`227454630`/`365922885`/`682036009` = -0.32、`66671811` = -0.84)。
  計測はセグメント中点、`bridgeSegmentY` は **ax→bx の直線上**を見ており、**別の点を見ている。**
- **ランプ区間で持ち上げが減衰して桁下が浸かる**
  `差` が `1.55` / `1.62` / `2.49` の行(必要量は 4.00)。smoothstep の途中で水面上に出きっていない。

### 構造的な問題

`足元 -6.19` に対し水面は `-5.3`。**水面は突き抜け防止マージンのぶん、設計上つねに地面より
0.5〜0.9 高い。** つまり地面基準の橋は**既定で水没する**のが正常動作で、
点ごとのクリアランス救済だけがそれを支えている。救済が1点でも外れれば沈む。

## 1. 修正指示

### 修正A【最優先・これが本丸】欠測を水位に混ぜない

**A-1. 「欠測」を呼び出し側から見えるようにする**

`terrainY` / `farNodeY` の `|| 0` は既存の広範な呼び出し元(地形メッシュ・当たり判定)が
依存しているので**変えない**。代わりに欠測を判定できる関数を1本足す。

```js
// part6.js
function terrainYOrNull(x, z) {
  const near = sampleGrid(nearElev, nearCX, nearCZ, NEAR_W, NEAR_D, NEAR_SEGS, NEAR_SEGS1, x, z, true);
  if (near !== null) return near;
  const wide = sampleGrid(wideElev, wideCX, wideCZ, WIDE_W, WIDE_D, WIDE_SEGS, WIDE_SEGS1, x, z, false);
  return (wide === null || wide === undefined) ? null : wide;   // ★ 0 に潰さない
}
// part5.js
function farNodeYOrNull(i, j) {
  return (typeof terrainYOrNull !== 'function') ? null : terrainYOrNull(i * FAR_STEP, j * FAR_STEP);
}
```

**A-2. `_computeWaterProfile` は欠測ノードを候補から外す**

```js
const h = farNodeYOrNull(i, j);
if (h === null) continue;          // ★ 欠測は「地形が無い」であって「標高0の地形」ではない
if (M[b] === null || h > M[b]) M[b] = h;
```

**A-3. ビン全体が欠測なら、そのポリゴンのプロファイルを確定させない**

全ビン欠測(= `near=NO` かつ WIDE も範囲外)なら `entry.waterProfile = null` にして、
`waterSurfaceYAt` も水面メッシュの高さ確定も**保留**する。
`rebuildAreaPolyMesh` が標高到着後に再計算するので、揃った時点で正しく確定する。
**不完全なデータで水位をでっち上げない**(大原則1と同じ)。

### 修正B【併せて必須】外れ値1点で川全体を持ち上げない

欠測を除いても、堤防・橋脚・中州の縁など「1点だけ高いノード」は残る。
現在の「ビン最大 → 累積最大で全域へ伝播」は、**その1点を川全体に配る増幅器**になっている。

- ビン内は **最大値ではなく高位パーセンタイル(例: 90%点)** を採る
  (ノードが1〜2個しかないビンは最大のままでよい)。
- 累積最大の伝播に**上限**を設ける。隣のビンから引き継げる上げ幅を
  `MAX_RISE_PER_BIN`(例: 0.5ゲーム単位/200m = 実勾配0.125%相当)までに制限する。
  実際の河川の縦断勾配を超える持ち上がりは、データ異常とみなして切る。

### 修正C 橋のサンプリングを実ジオメトリに乗せる(v1の4-4を必ず実施)

`heightAt(f)` 内の `ax + (bx-ax)*f` を廃止。`addRoad` の呼び出し元(`part8.js`)は
そのセグメントの実座標を持っているので、`bridgeY` に `sx,sz,ex,ez` を追加し、
`fracA → (sx,sz)` / `fracB → (ex,ez)` で `waterSurfaceYAt` を問い合わせる。
**実測で「別の点を見ている」ことが確認済みなので、これは推測ではなく確定した不具合。**

### 修正D 橋の持ち上げを「点ごと」から「way単位」へ

**設計思想の変更。これが再発を止める本体。**

現状は各点で「ここに水があるか」を聞き、外せば沈む。1点の判定漏れが即水没につながる。

```
1. way 構築時に、そのwayの実ジオメトリに沿って 20m 間隔で waterSurfaceYAt を密にサンプルする
2. 得られた水位の最大値 Wmax を way に1つ持たせる(全区間で共通)
3. 「水に掛かる区間」= 最初に水を検出した位置 s0 と最後の位置 s1
4. デッキ高さ = max(地面補間, Wmax + クリアランス) を s0..s1 の全域に一律適用
5. ランプは s0 より手前 / s1 より奥(=確実に陸地の側)にだけ置く
```

- **way が分割されていても、s0/s1 が両端に一致するだけで自然に処理される**(疑い1が消える)。
- 途中1点の判定漏れが致命傷にならない(最大値で全域を決めるため)。
- ランプが水上に掛からないので、`差 = 1.55` のような中途半端な持ち上げも消える。

### 修正E motorway(最後)

v1 の 4-5 のまま。`addMotorway` にも同じ `Wmax` 方式を通す。

## 2. 検証

修正A投入後、同じスニペットで再計測し:

## 3. 大原則への追記

16. **「データ無し」を既定値(0)に潰さない。**
    `|| 0` は欠測を「標高0mの実測値」に化けさせる。潰した瞬間、
    それが最大値・平均値の計算に混ざり、下流の全ロジックを汚染する。
    欠測は欠測として伝播させ、受け取った側が「保留する」判断をできるようにする。
17. **最大値と累積伝播を組み合わせない。**
    どちらも外れ値に対して単調増加なので、組み合わせると
    **1点のノイズを空間全体に配る増幅器**になる。
    片方を使うならもう片方はパーセンタイル・上限付きにする。
18. **救済ロジックは「点ごと」ではなく「オブジェクト単位」で決める。**
    1点でも判定を外すと破綻する設計は、実データの前で必ず破綻する。
