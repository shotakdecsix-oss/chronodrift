# 実装指示: coastline由来のポリゴンを地形マスクから外す — NYで陸が水面になる真因

作成: 2026-08-05 / 実機の座標実測(NY)で確定。変更は**2行**。

---

## 1. 実測

プレイヤー: `40.7032,-74.0148`(ハドソン川、バッテリーパーク西)

### マスクを付けているエントリの内訳(`maskNodes = 803`)

**`river` 上位2件 = 505ノード。これは正しい。**

| 中心 | サイズ | 実際の場所 |
|---|---|---|
| `40.7510,-74.0082` | 4.45 × 9.77 km | **ハドソン川** |
| `40.7179,-73.9865` | 4.82 × 6.72 km | **イーストリバー** |

`natural=water` / `riverbank` の実測輪郭。ここを穴あけするのは**正解**。二重登録でもない。

**`sea` 83件 = 残り。ここに陸が混ざっている。**

| 中心 | 実際の場所 |
|---|---|
| `40.7035,-74.0066` | 金融街(ウォール街付近) |
| `40.7042,-74.0041` | 同上 |
| `40.7104,-74.0053` | トライベッカ/シティホール付近 |
| `40.7032,-73.9958` | ブルックリン橋西詰(マンハッタン側) |
| `40.7104,-73.9788` | ロウアー・イースト・サイド |
| `40.7066,-73.9879` | トゥー・ブリッジズ |

一方 `40.7047,-74.0256` や `40.7033,-74.0176` はハドソン川内で正しい。
**正しいものと陸のものが混在している。**

---

## 2. 原因

**coastline の海側判定が、wayごとに当たったり外れたりしている。**
全体が反転しているなら全部が陸になるはずなので、単純な符号ミスではない。

マンハッタンは閉じた海岸線リングの島だが、ログの `nearIslands` はほぼ `0`。
**島として検出できていない**(リングがタイル単位の多数のwayに分かれ、閉じられないため)。
島判定に失敗した結果、各wayが独立に ribbon 化され、
**向きを外したものが島の内側(=マンハッタン)を海として塗っている。**

---

## 3. 修正(2行)

**coastline由来のポリゴンは地形マスクに使わない。**

```js
// js/legacy/part4.js
// Phase1 ribbon(:1278付近)
buildFixedFlatAreaPoly(poly,      waterAreaMat, WATER_VISUAL_MARGIN, seaY, holes, false);
// Phase2 whole-tile(:1358付近)
buildFixedFlatAreaPoly(wholeTile, waterAreaMat, WATER_VISUAL_MARGIN, seaY, holes, false);
```

### なぜ Phase1 も外すのか(前回の指示の訂正)

`IMPL_PROMPT_20260805_WATER_HOTFIX.md` で
「Phase1 ribbon は陸側の縁が実測 coastline なのでマスクしてよい」と書いたが、**これは誤り。**

ribbon は「海岸線 + 3000m沖側オフセット(`COASTLINE_SEA_FAR`) + タイルクリップ」で
**構築した**形状であって、実測された水域の輪郭ではない。
**向き判定を1本外すだけで、島の内側を丸ごと海にできてしまう。**

> **マスクに使ってよいのは、範囲そのものが実測されているポリゴンだけ。**
> 構築物(オフセット・クリップ・多数決)を形状判断の入力にしてはいけない。
> これは `IMPL_PROMPT_20260805_LAND_PATCH.md` 大原則25と同じ話で、
> 適用が甘かった。

### 穴は足りるのか

足りる。**必要な穴はすべて `natural=water` / `riverbank` から開く**(上表の river 2件 = 505ノード)。
ハドソン川・イーストリバーの水域は実測輪郭で正しく穴が開く。

海は実標高0m固定のまま描かれるので、`landFloorM` で0.5m以上に底上げされた陸は
**自然に海面を突き破って見える**(マスク導入前の挙動に戻るだけ)。

## 4. 検証

1. **`maskNodes` が 803 → 500前後に落ちること**(river 2件ぶん)
   落ちなければ、他にマスクしている経路が残っている
2. マンハッタン(金融街・ロウアーイーストサイド等)が**陸として見えること**
3. ハドソン川・イーストリバーは**水面として見えること**
4. 相模川がデグレしていないこと

---

## 5. 次に出るかもしれないこと(混ぜないこと)

沖合で「海面が地形の下に隠れる」が再発する可能性がある
(標高データが無い海上が `landFloorM` で0.5mに底上げされ、固定0mの海面より高くなるケース)。

**これは独立の課題。** 再発したら海の固定Yのオフセットで対処する。
**マスクの話と混ぜないこと。** 混ぜると今回と同じ往復になる。

---

## 6. 大原則への追記

35. **「実測」と「実測から構築したもの」は別物として扱う。**
    coastline のノード列は実測だが、
    そこから作った ribbon(3000mオフセット + クリップ)は構築物。
    **構築物は、描画には使ってよいが、形状判断(地形除去・当たり判定)の入力にしてはいけない。**
    区別は型やフラグで表現し、「実測輪郭のみ受け付けるAPI」を用意する。

36. **島・穴のようなトポロジーに依存する判定は、
    データが分割されて届く環境では成立しないと考える。**
    マンハッタンの海岸線リングはタイル単位のwayに分かれて届くため、
    「閉じた島」として検出できない。
    トポロジーを前提にした判定は、届き方に依存しない代替(実測ポリゴン)へ寄せる。
