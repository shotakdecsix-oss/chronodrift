# 実装指示: 水面の下の地形に穴を開ける(「浮く／沈む」の往復を終わらせる根治策)

作成: 2026-08-04 / 実測ログで確定。`IMPL_PROMPT_20260803_WATER_SURFACE.md` 5章の先送りを撤回する。

---

## 0. 結論

**水面と地形は「同じ面」になっている。** どちらの集約方法を選んでも直らない。

NY・バッテリーパーク沖の実測:

| 項目 | 値 |
|---|---|
| 標高パネル | **3m** |
| 付近の `[water] profile` | `min=17.0` 〜 `19.0`(ゲーム単位) |
| `elevBase` ≈ | -5.5 |
| 水位を実標高に換算 | `17.0 / 2 + (-5.5)` = **約3.0m** |

**水位と地面の標高が一致している。**

修正A(内側ノードのみ)は正しく効いた。効いた結果、水位は岸の高さではなく
**川面の地形そのもの**から作られるようになり、
`水面 = 地形 + WATER_MARGIN(0.3) + yOff(0.15) = 地形 + 0.45ゲーム単位(実測22cm)`
という関係になった。

一方:

- 地形メッシュ = **200m** 三角形(`FAR_STEP`)
- 水面メッシュ = **100m** 三角形(`subdivideTriangles` の `MAX_EDGE`)

**同じ `farSurfaceY` から高さを取っても、三角形の張り方が違えば辺の位置がズレる。**
200mセル内の起伏が1〜3mあれば、ズレは0.5〜1.5ゲーム単位。
**22cmのマージンでは必ず負ける。** 勝った所は青、負けた所は緑 = 実機の見た目そのもの。

> この10回、「浮く」と「沈む」の間を往復してきたが、
> **どちらも同じ1つの原因の裏表**だった。集約方法の調整では終わらない。

---

## 1. 方針: 水面の下から地形を無くす

`farMesh` のインデックスバッファを組み直し、
**4隅すべてが水面ポリゴンの内側にある200mセルは三角形を張らない。**

- 「4隅すべて」という条件により、**穴は必ず水面ポリゴンより内側に収まる。**
  → 水面が確実に覆うので、隙間から下(空)が見えることはない。
- 岸のセルは地形が残る。そこで多少食い合っても**「岸」に見えるだけで正しい。**
  消したかった突き抜けは川の真ん中で起きるもので、それが構造的に消える。
- **水位の精度要求が一気に下がる。** 川の真ん中に地形が無いので、
  埋まることも突き抜けることも起こりようがない。

## 2. 実装

### 2-1. 水マスク(200m格子ノード単位)

```js
// part4.js — 水面ポリゴンの追加/破棄のたびに更新する
const waterNodeMask = new Map();   // "i,j" -> true(そのノードが水面ポリゴン内側)
function _markWaterNodes(entry, on) {
  const i0 = Math.floor(entry.minX / FAR_STEP) - 1, i1 = Math.ceil(entry.maxX / FAR_STEP) + 1;
  const j0 = Math.floor(entry.minZ / FAR_STEP) - 1, j1 = Math.ceil(entry.maxZ / FAR_STEP) + 1;
  for (let j = j0; j <= j1; j++) for (let i = i0; i <= i1; i++) {
    const x = i * FAR_STEP, z = j * FAR_STEP;
    if (!pointInPolygon(x, z, entry.pts)) continue;
    if (entry.holes && entry.holes.some(hp => hp.length >= 4 && pointInPolygon(x, z, hp))) continue;
    if (on) waterNodeMask.set(i + ',' + j, true); else waterNodeMask.delete(i + ',' + j);
    _waterMaskDirty = true;
  }
}
```

- `buildAreaPoly` / `buildFixedFlatAreaPoly` で水域エントリを登録したとき `on=true`
- `dropAreaRecordsInTile` 等で破棄したとき `on=false`
- **`entry.waterNodeInfo` の収集ループと同じ格子**なので、そこに相乗りしてもよい(計算の重複を避けられる)

### 2-2. `updateFarMesh` でインデックスを組み直す

```js
// part5.js updateFarMesh の中、頂点高さを書いた後
if (_waterMaskDirty || cx !== farLastX || cz !== farLastZ) {
  const idx = [];
  for (let jz = 0; jz < FAR_SEGS; jz++) for (let jx = 0; jx < FAR_SEGS; jx++) {
    // このセルの4隅がすべて水中ならスキップ(=穴を開ける)
    const a = _isWaterNode(i0 + jx,     j0 + jz),     b = _isWaterNode(i0 + jx + 1, j0 + jz);
    const c = _isWaterNode(i0 + jx + 1, j0 + jz + 1), d = _isWaterNode(i0 + jx,     j0 + jz + 1);
    if (a && b && c && d) continue;
    // PlaneGeometry と同じ三角形分割の向きで push する(farSurfaceY の式と必ず一致させること)
    ...
  }
  farGeo.setIndex(idx);
  _waterMaskDirty = false;
}
```

**重要**: `farSurfaceY`(`part5.js:64-73`)は `PlaneGeometry` の三角形分割を前提に
「描画されるメッシュ表面と厳密に一致する」よう書かれている。
**インデックスを自前で作る以上、分割の向きを `farSurfaceY` と必ず一致させること。**
ここがズレると、プレイヤーの足元・建物・道路の高さが全部狂う(この一致は本プロジェクトの
数少ない健全な不変条件なので、絶対に壊さない)。

穴を開けたセルでは `farSurfaceY` が「存在しない面」の高さを返すことになるが、
そこは水面なので、**プレイヤー・当たり判定用には `Math.max(farSurfaceY, waterY)` を返す
`surfaceY(x,z)` を用意して差し替える**(水面の上を歩ける/泳げる扱いにする)。
これは `IMPL_PROMPT_20260803_WATER_SURFACE.md` 5章で挙げた注意点と同じ。

### 2-3. コスト

- ノード判定は 61×61 = 3721 回。`updateFarMesh` は200m移動ごとなので十分軽い。
- 判定結果は世界座標の格子に固定なので `waterNodeMask` にそのまま残り、再計算されない。

## 3. 今すぐ見た目を戻すための繋ぎ(任意)

穴あけまでの間、`WATER_MARGIN` を **0.3 → 2.0 ゲーム単位(実測1m)** に上げれば水面は出る。
200mセル内の起伏に対して勝てる量なので、緑の斑は消える。

**ただし川面が実測1m浮く。** これは「浮く/沈む」の往復に戻る道なので、
**穴あけを入れたら必ず 0.3 に戻すこと。**

---

## 4. 検証

1. NYハドソン川/湾で、**緑の斑が消え、一様に水面が見える**こと
2. 岸際で地形が水面より高くなっているが、それが**岸として自然に見える**こと
3. 穴から空が見えている箇所が**無い**こと(あれば「4隅すべて」の条件が緩んでいる)
4. プレイヤーが水面の上を歩ける(沈まない)こと ← `surfaceY` の差し替え漏れ検出
5. 相模川など**細い川で挙動が悪化していない**こと
   (200m格子に4隅とも収まるセルが無ければ穴は開かず、従来どおりプロファイルで描かれる)

## 5. 大原則への追記

21. **2つの面を「わずかな差」で重ねる設計にしない。**
    片方が他方から導出されていて、かつ三角形分割が異なるなら、
    **差がどれだけあっても分割の違いに負けうる。**
    重ねたい面が2つあるときは、
    (a) 分割を完全に一致させる、(b) 下の面を消す、のどちらかを選ぶ。
    「マージンを何cmにするか」という問題設定になった時点で、設計が間違っている。

22. **同じ症状が「浮く」と「沈む」で往復し始めたら、
    それは2つのバグではなく1つの原因の裏表である。**
    どちらかに寄せる調整をやめ、両方を生んでいる構造を消しにいく。
