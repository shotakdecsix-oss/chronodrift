# 実装指示 ④:設定(⚙)の文言と構造を整理する(D-3)

## 着手前に必ず

```
grep -n "perfBtn\|perfCtrl\|perfDesc\|perfLiteBtn\|perfStdBtn\|perfHighBtn\|seaCtrl\|charCtrl" index.html
grep -n "perfLite\|perfStd\|perfHigh\|perfDesc1\|perfBtnTitle" js/legacy/part1.js
grep -rn "PERF = \|perfPreset\|bMax" js/legacy/part1.js | head -20
```

## 前提(調査済みの事実)

1. **⚙ への統合は既に完了している。** `index.html:98, 477` のコメントに「アイコンが多すぎるので設定アイコン1つにまとめてほしい」というユーザー要望で `#seaCtrl` / `#charCtrl` を `#perfCtrl` に統合した経緯が書かれている。**この判断は正しいので戻さない。**
2. 現在 ⚙ の中には **描写 / 海面 / 時間帯 / キャラクター / 視点回転** の5系統が入っている(`#perfBtn` の `title` 属性がそれをそのまま列挙している)。**見出しによる区切りが無い。**
3. 現在の説明文(`#perfDesc`、i18nキー `perfDesc1`):
   ```
   軽量: 建物1.4km/低負荷(スマホ向け)
   標準: 建物2.2km
   高品質: 建物4.2km/先読み拡大(高性能PC向け・メモリ大)
   ```
4. i18n の仕組みが既にある(`data-i18n` / `data-i18n-html` / `data-i18n-title`、辞書は `part1.js` 冒頭。ja と en の両方)。

## 目的

⚙ を開いた人が、**数値を読まなくてもどれを選べばいいか分かる**ようにする。

## やること

### Phase 1:文言を「距離」ではなく「結果」で書く

プリセットのラベルと説明を書き直す。案:

```
🪶 軽量     遠くは見えないが、落ちにくい        スマホ・古い端末向け
🏘 標準     ふつう                              多くのスマホ向け
🏙 高品質   遠くの街まで見える。メモリを多く使う  高性能PC・新しいスマホ向け
```

- **距離(1.4 / 2.2 / 4.2 km)は消さずに、補足として小さく残す。** 自分でチューニングするときに必要。
- 日本語と英語の**両方**の辞書を直す。

### Phase 2:⚙ の中身に見出しを付ける

5系統を区切り線+小見出しで分ける:

```
── 描写 ──
  (プリセット3つ + 説明)
── 時間帯 ──
  (朝/昼/夕/夜/自動)
── 視点 ──
  (視点回転など)
── キャラクター ──
  (男の子/女の子)
── 海面 ──
  (海面高さスライダー等)
── デバッグ ──
  🩺 タイル状況
```

- 順番は「よく触るものほど上」。上記は一案なので、実際の中身を見て調整してよい。
- **`🩺 タイル状況` は「デバッグ」見出しの下に隔離する。** 常用者が誤って押す場所に置かない。
- **DOM の並べ替えと見出し追加だけ。既存のボタンの id・イベント配線は一切変えない。**

## やらないこと

- **プリセットの数値(`bMax`、描画距離)には触らない。** それは Phase 3 の話で、別タスク。
- ⚙ から項目を外に出さない(統合を巻き戻さない)。

## Phase 3(このタスクには含めない。別途判断)

記録に残っている未対応の宿題:

> **std(bMax 12000)より high(bMax 25000)の方が見た目上安定** とユーザー報告あり。今は記録のみ、対応未着手。

これが本当なら、**プリセットの名前と説明が実態と逆**ということになる(std で建物の生成/破棄が頻繁に往復してスラッシングしている可能性)。文言を直す前後で、この検証を別途行う価値がある。

**もし数値をいじる判断になった場合**:単独の理屈で決めず、**全プリセットで不等式を計算して見せること**([[feedback_pair_check_distance_constants]])。

## Phase 4(任意・将来)

初回起動時に `navigator.deviceMemory` / `navigator.hardwareConcurrency` / WebGL の `MAX_TEXTURE_SIZE` を見て、プリセットを自動選択し「おすすめ」バッジを付ける。ユーザーはいつでも変更できる。

## 完了判定

1. ⚙ を開くと、5系統が見出しで区切られている。
2. プリセットの説明が「何が起きるか」で書かれている。距離も補足として残っている。
3. **日本語・英語の両方で正しく出る**(`data-i18n` 経由になっていること。ハードコードしていないこと)。
4. 既存のボタンがすべて従来どおり動く(海面スライダー、時間帯、キャラクター切替、視点回転)。
5. `🩺 タイル状況` がデバッグ見出しの下にある。
